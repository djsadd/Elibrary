# Локальный запуск в Windows

Подготовлено 19 октября 2026 года. Открыть: http://127.0.0.1:5173/

## Что работает

Запущены веб-интерфейс Vite, API Gateway, Auth, Catalog, FileStorage,
Notifications, Reviews, Favourites и Garnet (совместимый с Redis сервер Microsoft).
Сервисы слушают только `127.0.0.1`. Данные находятся в отдельных SQLite-файлах
в `.local/data/`, загруженные файлы — в `.local/storage/`.
Это отдельное окружение разработки; оно не подключается к рабочим базам университета.

| Компонент | Адрес |
| --- | --- |
| Веб-интерфейс | http://127.0.0.1:5173/ |
| Документация API Gateway | http://127.0.0.1:8000/docs |
| Auth | http://127.0.0.1:8001/docs |
| Catalog | http://127.0.0.1:8002/docs |
| FileStorage | http://127.0.0.1:8003/docs |
| Notifications | http://127.0.0.1:8006/docs |
| Reviews | http://127.0.0.1:8007/docs |
| Favourites | http://127.0.0.1:8008/docs |
| Garnet / Redis protocol | 127.0.0.1:6379 |

Для входа созданы локальные учётные записи администратора и студента.
Адреса и случайные пароли сохранены в `.local/credentials.txt`.
Новые пользователи через интерфейс не регистрируются: регистрация отключена. Активностью и ролями управляет admin через защищённый метод `/api/auth/users/{id}/access`.
Каталог изначально пустой: дамп книг и рабочие пользовательские данные не предоставлены.

## Управление

Из корня проекта в PowerShell:

```powershell
.\.local\venv\Scripts\python.exe scripts/local.py status
.\.local\venv\Scripts\python.exe scripts/local.py stop
.\.local\venv\Scripts\python.exe scripts/local.py start
```

При повторном старте используются существующие базы, пользователи и JWT-ключ.
Скрипт не завершает чужие процессы на занятых портах. Остановка проверяет PID
и время создания процесса, затем завершает только сохранённые процессы и их дочерние процессы.

Если Node.js больше не находится автоматически, указать путь перед стартом:

```powershell
$env:ELIB_NODE = 'C:\полный\путь\к\node.exe'
.\.local\venv\Scripts\python.exe scripts/local.py start
```

Журналы: `.local/logs/<имя сервиса>.log`.
Чувствительное журналирование удалено. Старые журналы до исправлений могли содержать токены и тела запросов; они сохранены локально и не предназначены для публикации.

## Установленные зависимости

- Веб: установлены зависимости из `Frontend/tau-login/package-lock.json` через `npm ci`.
- Mobile: восстановлены зависимости из `Frontend/mobile/package-lock.json` через `npm ci`.
- Python: отдельное окружение `.local/venv`, без установки пакетов в системный Python.
  Полный список установленных версий: `.local/installed-requirements.txt`.
  Прямые зависимости выбранного локального набора: `scripts/requirements-local.txt`.
  Серверные requirements обновлены; JWT обрабатывается через PyJWT, новые пароли хешируются Argon2id.
- npm 10.9.4 размещён в `.local/tools/npm/`; глобальная установка не выполнялась.
- Garnet 2.2.3 размещён в `.local/tools/garnet/`, .NET Runtime 10.0.13 — в `.local/tools/dotnet/`.
  Runtime скачан с сервера Microsoft, проверен по SHA-512 из метаданных выпуска.
  Garnet скачан из [официального репозитория Microsoft](https://github.com/microsoft/garnet/releases/tag/v2.2.3).
  Описание совместимости: [документация Garnet](https://microsoft.github.io/garnet/docs).

Каталог `.local/` и вложенные `node_modules/` исключены из Git.
Сохранить `.local/`, чтобы пользоваться подготовленным окружением без повторной настройки.

## Ограничения

Это работающий основной набор сервисов, а не полный запуск `docker-compose.yml`.
Docker и настроенная WSL на этом компьютере не обнаружены. В исходном Compose
были также отсутствующие `.env.prod` и `AI/.env`; теперь они созданы скриптом `scripts/init_backend_env.py` с отдельными случайными ключами.

- Поисковый сервис не запущен: требуется Elasticsearch. Просмотр и поиск каталога
  через CatalogService доступны, отдельный полнотекстовый SearchService — нет.
- Analytics не запущен: его модели используют PostgreSQL JSONB; дополнительно
  предусмотрен ClickHouse. Сбор аналитики через middleware в локальном Gateway отключён.
- AI URL по умолчанию отключён. Для подключения нужен явно настроенный HTTPS endpoint.
- Интеграции с библиотечными системами и Platonus не проверялись на реальных аккаунтах.
  Письма, SMS, push и фоновые Celery-задачи не проверены. Запущен HTTP API уведомлений.
- ReportingService и ServiceRegistry содержат пустые `main.py` и не являются готовыми сервисами.
- Мобильные зависимости установлены, TypeScript проходит; Expo, эмулятор и устройство не запускались.
- Обнаруженные backend-проблемы исправлены и покрыты регрессионными проверками; границы проверки и оставшиеся задачи перечислены в `AUDIT_REPORT.md`.
- Старые JWT больше не принимаются. После обновления и после перезапуска локального Garnet потребуется войти заново.
- Для прямых FileStorage-загрузок и скачиваний нужны права сотрудника; читатели скачивают книги через CatalogService.

## Выполненные проверки

Сборка веб-интерфейса прошла. TypeScript мобильного приложения проходит после установки
зависимостей. Проверка Python-зависимостей `pip check` проходит.
Регрессионные проверки безопасности находятся в `tests/security/`, результаты — в
`.local/logs/security-tests-final.txt`. Дополнительно проверены реальный вход через
Gateway, загрузка и чтение файлов, отказ изменения роли, приватные книги, отключение
пользователя, повторный refresh и выход из сессии. Публичный интерфейс отвечает HTTP 200.

Backend pip-audit не обнаружил известных уязвимостей; Bandit не выдал high/medium.
Устаревшие frontend-зависимости и ошибки линтера требуют отдельной работы.

Запуск регрессионных тестов:

```powershell
.\.local\venv\Scripts\python.exe -m pytest tests/security -q
```
